Plan verification for the design scope named in the assignment. Read the brief, approved system, affected screens, states, widths, themes and supported languages; task gates determine authors, checkers and routing.

1. Record the design scope and acceptance criteria. Include realistic content, empty, loading, error and partial-data states, narrow and wide layouts, translated text, system fit and accessibility.
2. Select checks that prove those criteria. Author inspection and a separate task-assigned independent check are different evidence; an independent checker is not the author and does not edit the reviewed item.
3. Batch built-screen comparisons when the scope and reference version are shared. Define samples for system drift before inspecting them; record what a sample cannot prove. Do not create a recurring review merely because this ability is selected.
4. Measure contrast, token use, layout and overflow with scripts where available. Give code checks tests for both valid and rejected cases. If automation is unavailable, name the unproved check and the assigned manual alternative.
5. Validate model-based critique or brand checks against versioned examples labelled by someone other than the check's author, using the responsible owner's threshold. Revalidate when the check, prompt, lists or model changes. Count false accepts and false rejects separately, and add real misses. Unvalidated model output cannot establish approval.
6. Keep protected approvals explicit. A breaking system change needs the decision of the department's own responsible people, with affected products and implementation cost. No sample, model result or selected ability waives human approval or publication controls.

Return a verification plan with check scope, reference version, assigned owner, procedure, expected evidence, gaps and measures such as returned designs or findings by product. Record descriptions in the company-designated location when requested; staffing and turn cadence remain properties of the assignment.

For video editing, assign continuity and cut checks with the footage and references the checker needs. Route original production to Video production when it exists.
