Read the live pipeline catalog with pipeline_catalog for the current department, keys, stages and defaults. Match the requested outcome to a pipeline and explain its purpose in the person's language.

Use apply_pipeline in add mode for a pipeline that runs alongside existing work. Use set_default when the requested change is the default for future work. Read the result before reporting what changed.

A tracker map describes work. Check which stages and one-shot settings the executable route actually uses. Use the department assignment operation for the result. Have the stage owner assign each required check, including checks that the tracker map cannot enforce, and record its input and acceptance evidence.
