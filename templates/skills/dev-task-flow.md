You can deliver executable work through the required route with exact-version evidence.

Read the current task and task.echelons before changing code. When task.echelons is turnkey, the task is yours end to end alone on its task branch: code, local checks of named test files for your changed area and callers, build, types and lint, your own review and security check, with no echelons and nobody else called onto it; hand in the branch: take it into the turn branch yourself, where your department keeps turns, and close it with report done true and the evidence in the same turn, naming the exact commit you checked, one you made on your own branch, and the commit right under your first own commit, which is another branch's commit where you built on one. Fast-forward the turn branch to your checked commit and push; where the turn branch went on, take it into your branch first, then fast-forward. A release counts as checked only the first-parent line from your named commit down to where your branch started: a merge made on the turn branch, or a commit under or on top of your line, goes to a person. Wait for nobody's go-ahead, for no release to ship and for no next turn to open: the turn branch never stops, and what joins it after a release's commit goes into the next release by itself. A clean merge of the turn branch needs no new checks, as the release's whole run checks everything together; after a conflict you resolved, check the files you touched. Work in its named repository and branch, never directly on main. Keep each connected result with one author end to end and one current owner. Preserve other writers' files and workspaces.

Architecture produces a concrete plan unless the task is small. Development writes tests before implementation: observe the intended failure, make the change and run only affected checks, naming them, in your own workspace. Configuration failure, a missing stage or zero selected tests is not PASS.

Commit and push the actual branch. Submit changed paths, requirement -> test links, actual output, full base and candidate SHAs. Every executable result then passes Review. Review owns its repairs in the same branch; ordinary findings do not return to the original author. A result pursuing the wrong goal goes to the head. The next checking owner is another employee using a model not weaker than the producer. Prefer another provider when available; the same provider, subscription or tariff is allowed without waiting for a second provider.

Cleanup is absent by default. Only the head enables this optional stage for a task or turn after Review, using the existing cleanup ability offered off to developers and reviewers. Security follows when the head identifies risk or Review adds it with a reason. Read the Security evidence for the exact candidate.

External Review and Security engineers work only in echelon tasks. In an echelon task, any change affecting access, root, permissions or secrets must pass an independent Security engineer before it reaches any shared branch, including the turn's branch, for urgent and small work and review fixes too; self-review does not replace this gate. A member of a turnkey team does and releases its task end to end alone, with its own review and security check, and calls no external checker.

Tests checks the final candidate including every repair locally, by the test files the change reaches. Mutations cover only changed pure functions with direct fast tests. Report finished check evidence for that exact candidate. Use the route's repair step to return a source defect to Development with the exact candidate and failing evidence. Keep test-only repairs in Tests when its route permits. When the candidate's own change passed and it only needs the main line or the open turn branch of its own department taken in (the turn takes a candidate only by fast-forward), it stays at Tests: merge the current head of that line into the candidate's branch, push it, use "submit" with review.baseCommit naming the commit you took in, and check the new candidate. A coordination-only parent reports its child results without an invented code SHA once every child is done or cancelled, whichever way each closed: only open child work blocks it, and a child with no accepted current result is recorded as closed without one, never as accepted. A parent with executable output follows mandatory Review.

After Tests, follow the task's authorized integration route. A generic wake-up naming another branch cannot override an explicit restriction in the task. Follow the department's commit rule before pushing to main. With no rule, continue once the checks on the exact commit pass. If approval is required, ask for that commit before pushing and use the responsible person's answer, the answer of the orchestrator acting for the owner, or recorded auto-approval under the department's autonomous release. Passing checks grants no release, live-data, access or model-change permission.
