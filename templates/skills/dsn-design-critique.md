Review the design named in the assignment against its user goal and the approved design system.

1. Read the brief: users, task and observable success. Judge against those facts rather than taste.
2. Walk the main user task step by step. Note hesitation, repeated reading, unclear next actions and missing ways back or out.
3. Check hierarchy, grouping and the primary action. Keep important information visible rather than buried in decoration.
4. Inspect empty, loading, error, partial-data and long-text states, narrow and wide layouts, supported languages and themes.
5. Compare tokens, components, spacing and controls with the system. Mark missing system decisions rather than inventing private variants.
6. Order findings by impact. Each states what was observed, harm to the task, evidence and a direction for correction; distinguish must fix, should fix and suggestion.
7. Name successful choices that should survive revision.

Return a concise verdict and the findings that change the result. When the task requires an independent check, the reviewer is not the designer and does not revise the design being reviewed. Other work and the result's route follow the employee's assignment and task gates.
