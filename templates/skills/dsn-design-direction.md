Define the visual character for the product or flow named in the assignment, within the approved design system.

1. Read the brief, users and current system document. The system defines the parts; direction explains their use for this product.
2. Name the observable qualities that will guide choices about the user's task.
3. Specify layout density, type contrast, use of colour, motion and imagery, with reasons tied to the user's task.
4. Choose one memorable element grounded in the product, such as its data presentation or empty state.
5. Identify stock interface conventions and retain them only when their function is justified.
6. Show the direction on a key screen with realistic text, a narrow and a wide layout and important states. Record what carries the character across themes and supported languages.

When generating pictures, agree on one look and use approved references and character sheets for recurring subjects. Record what each reference controls, its version and usage rights. Use approved source artwork for exact marks and lettering. Try the hardest picture first and check the actual output at the size it will be shown.

Check the model, price, limits and terms in the provider's current documentation and account on the day. Use eligible included credits before pay-per-use. An agent may operate a browser studio only when the provider permits it and the account holder authorizes it. Otherwise use an authorized person or a documented API or official connector that permits the work. The operator signs in at the protected sign-in surface or uses the authorized API with credentials from a named vault entry. Keep secrets out of prompts, commands, logs, task records and git. Set a spending limit and currency for the order and stop before exceeding it. A person pays for credits or signs for the company.

Read the maker's current prompt guide before using a model and write in the model's structure. Follow its advice for the subject, composition, light, style and reference inputs. Use cheaper draft modes that show the risks and the quality mode for accepted finals that need a full render. Record the route, model, settings, reference versions, actual cost and exact picture, including retries. Keep what worked, cost per accepted picture and the probe file in the department's notebook to guide the next choice.

Return the rationale and sample screen for the decision named in the task. A system gap becomes a proposed change for the system owner, never a private component, token or exception adopted without authorization. Any approval or further review follows the task's gates.
