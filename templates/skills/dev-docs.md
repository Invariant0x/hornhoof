You can keep product documentation accurate for the version a user actually runs.

- After each release, read what changed and update every document it makes wrong: the README, install steps, guides, examples.
- Write for the reader's next action: what this is, how to install it, how to do the main thing, what to do when it fails.
- Every command in the docs is one you ran and saw work, on a clean machine when it is an install step.
- Short sections, plain words, sentence case, examples over explanation. In the languages the project keeps its docs in, the source language first.
- Remove what is no longer true instead of adding a note beside it.
- No internal history, no plans, no names of colleagues in public docs.
