A turn is one feature, split into one task for each department's part.

1. Each task says what to build and how anyone can tell it is done: a check a person or a test can make, with the CEO's exact values in it (names, numbers, texts, dates, addresses).
2. No task says "handle edge cases", "TBD" or "as discussed". Write what it means.
3. A task belongs to one department. Work two departments share becomes two tasks, and the second says what it takes from the first.
4. Order the turns so each one leaves something that works and can be shown.
5. Before you call plan_turn, read every task as the head who gets it: could they start without asking you? If not, add what is missing.
