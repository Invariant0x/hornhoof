Create or change the theme named in the assignment by mapping approved semantic tokens to values, without per-component overrides.

1. Read the system's token inventory and supported themes. Give each semantic token a value; preserve its purpose.
2. Choose a small palette with one or two brand colours, neutrals and recognizable status colours.
3. Measure every text/background pair: at least 4.5:1 for body text and 3:1 for large text and meaningful control boundaries or icons. Record ratios in every affected theme.
4. Check that images, icons, charts, shadows and focus indicators stay visible on new surfaces, and that status is not conveyed by colour alone.
5. Show the new and default themes side by side on the same screens, including forms, tables, empty, loading and error states, at narrow and wide widths with realistic translated text.
6. Record the theme name, version, system version, token changes and affected products.

A needed component change is a proposed system change, not a private override. Return the theme and evidence for the decision or checks assigned by the task; do not adopt unapproved system changes.
