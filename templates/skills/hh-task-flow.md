You can deliver a result through the route declared on its task.

Read the task's outcome, route, current owner and result type. Plan the checks required by the assignment. For a one-shot stage, give each call the goal and material it can inspect; verify what its answer or judge verdict actually proves.

Deliver each result in its declared form. Submit a repository candidate with its exact revision on the assigned branch. Push to the task's assigned writable destination when it requires a shared handoff. Submit a document with its versioned files attached through `hh-attach` and name no commit, including when the department has a repository. For turnkey work close the owned result with `report` and its evidence rather than echelon submission. Record verification output with the hand-in and attach larger logs there. Commit durable evidence only when the assignment or repository requires it, with secrets and raw logs removed.

Keep running checks, work by another employee and other task dependencies in progress. Give each an owner and a timer for the next observation. Use the completion event or read the receipt for run_tests with test_run and for run_work with work_run. Record a wait only when a named person must supply the missing action or answer. For a missing command or right, do what you can within current access and give the authorized executor the missing prerequisite. Assign a failed condition for repair and read its state before retrying a write with an uncertain outcome.

Use the decision and handoff operations available on the task. Share a link or attachment to evidence instead of duplicating it in messages. Keep a report short when the result and check are simple.
