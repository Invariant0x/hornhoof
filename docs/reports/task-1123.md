## Architecture

The host still refuses completion during a tool, question, retry, restart, undelivered prompt or draft. The server queries the running job's exact node and checks the job and program instance twice at least two minutes apart.

1. Codex: recognize its completed `Worked for ...` line immediately preceding the current empty input. Recorded Codex 0.166.0 screens cover completion, ongoing work, drafts, retries and questions. An earlier completed response followed by newer output cannot close the current turn.
2. Antigravity: recognize the explicit idle footer of its current ruled input, with response content above it. Recorded Antigravity CLI 1.4.12 screens cover complete, busy, interrupted, queued, setup and trust states. Busy `esc to cancel` is distinct from the idle `? for shortcuts` footer. Pending questions remain authoritative.
3. Kimi: investigate upstream 2.5.1 before choosing evidence. Its activity renderer removes the spinner after completion and adds no successful completion line. Thus a blank prompt plus no spinner cannot satisfy the task's positive-proof requirement. Its renderer also emits explicit root program status `done` (OSC 7501), separate from child status and blocked questions. Using that raw terminal signal and enabling its documented switch needs the head's decision because it changes the screen-only plan. Until resolved, ambiguous Kimi screens remain working. Synthetic evidence must name the exact upstream commit and is not a production capture.
4. Process exit is a separate case: verify the existing host path from an actual dead pane to `job.program: gone` and failed job completion on a controlled clock. Add a server regression for an authenticated `gone` report whose final `job.done` is lost while the node still holds the job. Recover only from that exact job's recorded terminal exit, after a grace period; never infer exit from `no_program`, missing reports or an unchanged screen.
5. Check changing idle chrome: Kimi rotates toolbar tips every 10 seconds. Full raw-screen equality would reset the idle interval. Preserve response and instance continuity while excluding only proven non-progress chrome, or introduce explicit completion evidence if required and approved. Unknown layouts must reset evidence.
