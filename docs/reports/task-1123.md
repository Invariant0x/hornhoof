## Result and Architecture

A lost end notification no longer leaves a completed Codex, Kimi or Antigravity response running indefinitely when independent completion evidence is available. The node recognizes completion separately from hook-driven busy state. The server queries the running job's exact node and requires matching job and instance, empty input, no question, tool or undelivered words, and two fresh observations at least two minutes apart. Changed work, response, instance or unavailable evidence restarts observation.

The head authorized starting before task 1109 acceptance at 22:31 UTC on November 16. Architecture was reported and accepted at 23:07 after the head removed the task dependency and authorized the Kimi status path at 23:04. The head approved 19 paths on November 17, excluding CHANGELOG.md. Release owner Zee writes the combined release notes.

- Codex uses its completed `Worked for ...` line immediately above the current empty input. Earlier completed responses followed by new work or a question do not qualify.
- Antigravity requires its current idle footer at the end of the capture and response content after the latest user prompt. Initial input, busy, queued, interrupted, trust, draft and unknown dialog layouts do not qualify.
- Kimi 2.5.1 has no positive successful completion line on its plain screen. Its renderer publishes explicit OSC 7501 root status. The launch now enables PI_PROGRAM_STATUS=1. Only root `state=done` with `app=kimi-code`, read after the current turn's recording position, qualifies, together with the recognized empty input. Missing, working, blocked, error, child, malformed and incomplete status cannot supply completion. A new turn gets a new recording position. Work and recording identity are rechecked after an awaited read.
- An optional bounded SHA-256 completion digest carries response continuity in ProgramView. Kimi's rotating footer is excluded; the response remains included. The visible terminal cells are unchanged. Older node views retain full-screen continuity.
- Actual process exit is separate from an idle response. The existing node exit path already reports gone and returns a failed Kimi result without a hook or wire end. The new server recovery handles an authenticated gone report whose final job.done is lost while the node still holds the job. After two minutes it fails that exact job and cancels its old hold before pumping the queue. A foreign report or subsequent work cannot prove exit. Neither no_program nor silence proves exit.
