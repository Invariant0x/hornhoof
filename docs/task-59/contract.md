**Bounded exchange.** Prepare target first, source second. Target may report an already matching destination; after a fresh authorized check/commit it returns mode=already_present without writing. Otherwise source prehashes the pinned regular file before any bytes leave it. Server requests the exact next offset, source returns at most32768 bytes as canonical base64, server checks size/offset and hashes them, forwards once, and waits for target ack after write before requesting another chunk.2012762 bytes require62 chunks, last13914 bytes. No other in-flight chunk or buffering of the full archive. Task43 frames are at most49152 UTF-8 bytes, data at most43692 base64 chars; reject duplicate/out-of-order/overrun/extra chunks. Per-channel retained payload buffers are bounded to512KiB; existing socket parser's4MiB ceiling remains a separate preexisting transient bound. If socket bufferedAmount exceeds262144, fail this attempt instead of queueing more data. After exact EOF/source post-check and server hash match, target rereads/hashes/fsyncs its temporary FD and reports verified. Only then may server reauthorize and issue the one commit. Source and target final metadata must agree with the fixed tuple. Late frames from another attempt, wrong node/role, old connection or wrong phase cannot advance state. Malformed transfer frames fail the transfer without changing ordinary job/session state.

**Filesystem boundary.** Add one fixed internal helper, /app/task43-file.py, launched only by the node adapter as `/usr/bin/python3 -I /app/task43-file.py` with shell=false, minimal environment, bounded pipe protocol and a trusted work/agents root FD inherited as fd3. No caller selects executable, argv, environment or root; no remote exec interface exists. Runtime paths derive from configured dataDir/work/agents, not the sample deployment path. Do not create either agent workspace or change existing permissions. Walk each component using dir_fd with O_DIRECTORY|O_NOFOLLOW; open the source with O_PATH|O_NOFOLLOW, require a regular inode and exact size, then read that pinned inode through its kernel FD. Hash before streaming and hash actual streamed bytes; compare dev/ino/size/mtime_ns/ctime_ns and the original directory entry afterward. Path substitution never selects another inode; any change fails before publication.

At target, pin its existing workspace FD. Create an unnamed O_TMPFILE|O_RDWR file inside it, mode0600, without O_EXCL. Bound writes to the exact size; preserve existing workspace ownership for the new file or fail without changing existing files/users. After target hash and fsync, publish the pinned temp inode with `os.link('/proc/self/fd/<tempfd>', basename, dst_dir_fd=workspacefd, follow_symlinks=True)`. This is the Linux linkat FD-source path, atomically no-clobber. No check-then-rename fallback. EEXIST opens the existing basename without following symlinks: exact regular size/hash means already_present, anything else means destination_conflict, untouched. Fsync the directory; reopen final without following links and verify it is the intended inode/hash before stored acknowledgment. Revalidate workspace anchor identity before/after publication; do not report success for a replaced workspace. Closing an unpublished unnamed FD, including crash/EOF, leaves no named partial file. A published file is never deleted on uncertain acknowledgment. Python dir_fd operations and Linux FD-source link semantics are documented in [Python os](https://docs.python.org/3.11/library/os.html#os.link) and [linkat](https://man7.org/linux/man-pages/man2/link.2.html). These are design prerequisites, not a claim about installed nodes. Helper/procfs/O_TMPFILE/hard-link/fsync support must pass isolated synthetic qualification before capability advertisement; otherwise return unsupported_node, never weaken the path boundary. Node processes/filesystems form the trusted execution boundary; this does not isolate a compromised node from its own files.

**Receipt, failure and retry.** Return metadata only and append it through existing task engine note/published into task_events on56: kind=comment,data.task43Transfer=<strict receipt>. Receipt has actual runtime task/company/job, source/target agents and paths, expected and separately nullable actual size/hash, request/attempt ids, source-read/target-verified/stored/server-received UTC, mode and error. Never fill unknown actual values from expected constants. Node UTC is attributed; server UTC records receipt. server_complete requires a stored acknowledgment from the pinned target after exact size/hash, durable publication and final-file check. RPC success/relay EOF alone is insufficient. Disconnect or timeout before commit returns failed; after commit without proof returns failed/commit_outcome_unknown,mayExist=true. No false assertion that the destination was removed. Retry needs a new valid56 job if the old one ended, plus the same requestId and exact policy. It always rechecks the receiver file; a historical receipt alone never proves present contents. Matching bytes are safely already_present; a different existing file is never overwritten. New attempt ids fence old frames; no automatic background retry.
