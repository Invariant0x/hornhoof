## Proposed refactoring order

1. **Start four independent slices.** Assign server authority and approvals to one owner, web tracker and screen boundaries to another, node provider/terminal boundaries to a third, and evidence plus stale documentation to a fourth. The web slice can consolidate existing presentation contracts while authority behavior is being decided.
2. **Agree on shared contracts before changing them.** Settle the irreversible-deletion proof, department approval defaults, supported node and server overlap, and treatment of retained outbound data. Then run instruction delivery, gateway retirement, and test-receipt compatibility as separate slices with one owner per protocol or migration change.
3. **Break the server cycle at the smallest edges.** Land the error/keeper fix and task engine/tracker cut first. Follow with queue, node dispatch, and test-run extractions. Give updater and keeper handoff work its own owner because it shares durable state with rollback and restore.
4. **Run test cleanup alongside its owning slice.** Replace fixed waits and duplicate assertions as the corresponding modules move. Reprofile the historical slow files on the merged branch, then remove compatibility code and retained artifacts whose consumers have been accounted for.
