## Proposed refactoring order

1. **Fix lifecycle correctness first.** Give People removal, backup carry/restore, one-shot completion, tracker reassignment and employee history to separate owners. Agree on removal-record semantics between People and Restore before either changes their shared contract.
2. **Run independent cleanup in parallel.** One owner can fix screenshot output and archive evidence. Others can remove obsolete staging material, merge test fixtures, repair port allocation, or extract the keeper error message. These slices have little production-file overlap.
3. **Settle product policy before changing gates.** Give one owner the authority matrix covering orchestrator actions, irreversible deletion, department rules and machine-owner grants. A second owner can reconcile skills and guides against it. Give instruction transport and scheduling separate owners because they have different compatibility and failure modes.
4. **Cut import cycles from the leaves inward.** Start with run constants, job lookup, tracker revision, repository refs and provider isolation. Then split the task engine, conversation queue, terminal host and updater. Assign each large file to one person until its public entry points stabilize.
5. **Finish with contracts and compatibility retirement.** Publish the shared catalogs, view types and test identities first. Switch web, server, node and scripts independently. Remove mixed-version paths and retained gateway data only once their support floor and retention decisions are recorded.
