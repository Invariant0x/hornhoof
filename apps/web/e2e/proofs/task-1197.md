# #1197 — доказательства проверки

Проверенная версия кода: `b1a16beeab59126545dd6522a56d8310eb2b0be8`. Основа: `a27bc368b1e027af70883d06d1da9ba2b07985ab`. Этот файл добавляет только отчет.

Причина: Settings обращается к `/api/vault`, чтобы определить состав навигации, даже пока группа паролей закрыта. Реальный GET возвращает `{ entries }`; отдельного DTO хранилища в protocol нет, поэтому мок использует экспортированный тип `VaultEntry` клиента. Локальный мок возвращает `{ entries: [] }`. В матрицу ожидаемых групп добавлены пароли, включая человека с ограниченной видимостью отделов. Продуктовый код Vault, assertions и лимиты не менялись.

RED: исходный Chromium-сценарий дал 12 ответов 404 на `/api/vault`; лог приложен к задаче. GREEN: тот же сценарий прошел. Для трех движков отдельная конфигурация собирает веб и проверяет его через Vite preview, один worker, retries 0.

Итог на проверенной версии: settings-groups.spec.ts — 120 / 120, по 40 в Chromium, Firefox и WebKit; Settings.test.tsx и Vault.test.tsx — 36 / 36; web tsc, eslint и build — exit 0. Авторский селектор не запускал браузерные сценарии: его nothing_selected не считается исполнением. Полные наборы и run_tests не запускались. Самопроверка и проверка безопасности: локальные тестовые ответы соответствуют настоящему контракту; права и секреты продукта не меняются.
